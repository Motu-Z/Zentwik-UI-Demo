# 下拉框（ComboBox）验证记录

> 结论：**本轮不提供下拉框样式**，调校页的方案选择改用分段控件。
> 本文件记录已排除的可能性与后续复做时的前提，避免再走一遍死胡同。

## 一、现象

在调校页写一个自绘 ComboBox（触发器 + Popup 弹层）后，离屏截图模式里
「打开弹层」这一步会把进程卡住：

```
--screenshot out.png --page=Tuning --dropdown
```

进程不退出、UI 线程停在等待态、渲染线程持续空转（CPU 占用不降）。

## 二、已排除的可能

| 假设 | 验证方式 | 结果 |
|---|---|---|
| 自绘模板写错了 | 换成**系统默认 ComboBox 模板**（完全不用自定义样式） | **同样卡住** → 不是模板的问题 |
| 弹层里用了裸 `ItemsPresenter` 导致找不到宿主面板 | 改成规范写法 `<StackPanel IsItemsHost="True" />` | **仍然卡住** → 不是这一条 |
| `Popup.AllowsTransparency=True` 走更新分层窗口路径导致渲染空转 | 改成 `False` | **仍然卡住** → 不是这一条 |
| 页面上 `SelectedIndex` 双向绑定造成回环 | 摘掉该绑定 | **仍然卡住** → 不是这一条 |
| 触发器命名/焦点逻辑 | 触发器改名为 `ToggleButton`、独立模板 | **仍然卡住** → 不是这一条 |

结论：**卡住的是「在应用启动阶段程序化打开 Popup」这个动作本身**，
与 ComboBox 模板、与本工程的自绘样式都无关。

## 三、为什么不能就此上线

系统默认模板同样卡，说明这个挂起很可能来自运行环境（启动期的
PresentationSource / 焦点与激活时序），而不是控件实现。

但**真实用户点击**这条路径在本机无法验证：

- `Add-Type`（编译注入 Win32 调用）被安全策略拦截 → 无法注入真实鼠标点击；
- `UI Automation` 的 `ExpandCollapsePattern` 走不通 —— 它内部同样落到
  `IsDropDownOpen = true`，属于同一条「程序化打开」路径。

也就是说：能证伪「模板写错」，但**无法证实「真实点击不会卡」**。
在这种情况下把弹层类控件放进共享样式表，等于给后来人埋雷，
所以本轮撤下样式，页面改用**无弹层**的分段控件。

## 四、复做下拉框的前提

要重新做自绘 ComboBox，请先满足以下条件，再按规范结构实现：

1. **先拿到交互式验证能力**（人工点一次，或放开鼠标注入），
   确认「打开弹层」在真实点击下不会卡。
2. 弹层宿主必须是 `<StackPanel IsItemsHost="True" />`，
   不能写成裸的 `<ItemsPresenter />`。
3. 触发器必须命名为 `ToggleButton`（WPF 按这个名字找它），
   且 `IsChecked` 双向绑回 `IsDropDownOpen`（选中项后才会自动收起）。
4. 弹层宽度固定值要与触发器宽度一致 —— 弹层与触发器分属两棵可视树，
   跨树拿 `TemplatedParent` 不可靠。

模板骨架本轮已写完并通过编译（见提交历史），可直接取用。

## 五、附：本轮新增的诊断开关（保留，有用）

| 开关 | 作用 |
|---|---|
| `--size=1180x1500` | 指定离屏渲染尺寸（页面比窗口高时用得上） |
| `--scroll=bottom` | 拍图前把页面滚到底（拍折叠线以下的内容） |

两者都只影响离屏截图，不影响正常运行。
